Turn an Ubuntu computer into an automated radio-station audio source

Published September 27, 2026 · Resonance Radio

The computer you already own can replace a mixer, cart machine and dedicated playout system for the first version of the station.

Start simple

A playlist application is enough to prove the entire RF chain. Create a folder containing music or other audio you have the rights to use, station IDs, test tones and spoken announcements. Normalize levels so transitions do not cause dramatic modulation changes.

Suggested signal chain

Ubuntu PC → audio output → AM transmitter → receiver

Keep software gain below clipping and set final modulation at the transmitter while monitoring the received envelope/audio.

Automation features worth adding later

  • Scheduled station IDs.
  • Time-of-day playlists.
  • Automatic loudness normalization.
  • Pre-recorded reviews and build updates.
  • Logging of what played and when.

Why not start with a huge broadcast stack?

Complex automation software introduces more failure modes before we know whether the RF chain is clean. The first milestone is several hours of stable playback from a basic playlist. Once that works, moving to Mixxx, Liquidsoap or a web-based scheduler is straightforward.

Copyright matters

Owning an audio file does not automatically grant public-performance rights. For experiments, use material you created, appropriately licensed music, public-domain material or speech/test content whose rights are clear.

Build a station clock before a station stack

A useful first automation can be a one-hour folder: opening ID, program blocks, short spoken links, a mid-hour ID and a closing segment. Render or schedule that hour repeatedly and listen for level jumps, dead air and clipping. Once the audio hour survives unattended playback, adding metadata, web control or more elaborate scheduling has a clear purpose rather than being software for its own sake.
